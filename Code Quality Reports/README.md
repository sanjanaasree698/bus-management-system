# Code Quality Reports Documentation

This directory provides documentation on how to interpret and analyze the automated code quality and security reports generated by the GitHub Actions workflow (`.github/workflows/code-quality.yml`).

---

## 📋 Overview of Reports & Scanners

The workflow integrates three security and code quality analysis tools:

1. **GitHub CodeQL Analysis**
2. **Semgrep (OWASP Top 10 Ruleset)**
3. **npm Audit (Dependency Scanner)**

---

## 🔍 1. GitHub CodeQL Analysis

### What it checks:
CodeQL is GitHub's semantic code analysis engine. It treats code as data to query for complex structural issues, security anti-patterns, data flow risks, and code quality flaws in JavaScript/TypeScript/Node.js code.

### Output File:
- `codeql-results/*.sarif` (SARIF format: Static Analysis Results Interchange Format)

### How to read the results:
- **GitHub Security Tab**: Results automatically populate under the **Security > Code scanning** tab of your repository.
- **VS Code Extension**: You can view `.sarif` files locally using the official **SARIF Viewer** extension in Visual Studio Code.
- Key fields in SARIF:
  - `ruleId`: The specific pattern identifier.
  - `level`: `error` (High priority), `warning` (Medium priority), or `note` (Informational).
  - `locations`: The exact line number and file path where the pattern was detected.

---

## 🛡️ 2. Semgrep (OWASP Top 10)

### What it checks:
Semgrep is a fast static analysis tool that matches patterns against source code using rules tailored for common security risks, including the **OWASP Top 10** categories (e.g., injection, broken authentication, hardcoded secrets, misconfigurations).

### Output File:
- `semgrep-results.json`

### How to read the results:
- Open `semgrep-results.json` in any standard text editor or JSON viewer.
- Focus on the `"results"` array:
  - `check_id`: Name of the rule triggered (e.g., `javascript.express.security.audit`).
  - `path` & `start`: File path and exact line number.
  - `extra.message`: Description of why the rule matched and recommended defensive practices.
  - `extra.severity`: `ERROR`, `WARNING`, or `INFO`.

---

## 📦 3. npm Audit (Dependency Review)

### What it checks:
`npm audit` checks package dependencies (`package.json` and `package-lock.json`) against the GitHub Advisory Database for known publicly disclosed vulnerabilities (CVEs) in third-party Node modules.

### Output File:
- `npm-audit-results.json`

### How to read the results:
- Open `npm-audit-results.json` or inspect the CLI output.
- Key elements:
  - `vulnerabilities`: Object mapping dependency names to their security advisories.
  - `severity`: `critical`, `high`, `moderate`, or `low`.
  - `recommendation`: Recommended package version updates to resolve the advisory (e.g., run `npm audit fix`).

---

## 📊 Summary Tab in GitHub Actions

After every workflow run:
1. Navigate to the **Actions** tab on GitHub.
2. Select the latest run of **Code Quality & Security Review**.
3. View the **Summary** tab at the top of the workflow page for an overview of status and downloadable artifact links.
